# CONTRIBUTING

## Ветки

- `feature/<номер-issue>-краткое-имя` — новая функциональность;
- `fix/<номер-issue>-краткое-имя` — исправление;
- `docs/…` — правки только документации;
- `chore/…` — инфраструктура, CI, зависимости.

Под одну задачу заводится одна ветка и один PR. Ветку создаём от свежего `main`.

## Коммиты

Conventional Commits: `feat:`, `fix:`, `test:`, `docs:`, `chore:`, `refactor:`.
Заголовок до 72 символов, в императиве; подробности — в теле.

## Pull Request

- Открыв PR, сразу назначьте рецензента из команды (Reviewers).
- Diff до ~400 строк; больше — делим на несколько PR.
- В описании: что делает, как проверить (команда или сценарий), `closes #N`.
- В `main` попадаем только через PR. Прямые push и force-push запрещены.
- Вливаем после содержательного review: «ок» и пустой approve не считаются
  (правило курса).

## Review

- Задача рецензента — найти проблемы: что сломается, чего не хватает в тестах,
  что непонятно. Лучше комментариями к конкретным строкам.
- Срок на review — 24 часа.
- Автор отвечает на каждое замечание: исправил или объяснил, почему не надо.
- За 48 часов до срока практики задачу без PR может перехватить любой участник
  (правило курса); о перехвате пишем в issue.

## Definition of Done

1. Выполнены все критерии приёмки из issue (каждое «Дано/Когда/Тогда»).
2. Новое поведение покрыто тестами: позитивные и негативные; для регэкспов и
   правил — параметризованные.
3. `pytest` зелёный локально и в CI (GitHub Actions).
4. Обновлены затронутые документы: README, `docs/requirements.md`.
5. Получено содержательное review, замечания закрыты.
6. PR влит, issue закрыта через `closes #N`.
