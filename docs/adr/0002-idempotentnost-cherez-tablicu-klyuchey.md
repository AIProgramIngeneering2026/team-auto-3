# ADR-0002. Идемпотентность создания отчёта через таблицу ключей

Дата: 2026-11-16
Статус: принято

## Контекст и ограничения

Создание отчёта меняет состояние системы (Job, работа анализаторов), поэтому
повтор запроса не безобиден: двойной клик, ретрай прокси, обрыв связи после
того, как сервер всё сделал (К1, К2 из колоды). Клиент у нас бывает человеческий,
никакой координации между его попытками нет. Один отчёт по организации может
быть легитимно создан несколько раз в разное время — значит, естественный ключ
`organization_id` не годится как ключ идемпотентности.

## Решение

Идемпотентность обеспечивает клиент заголовком `Idempotency-Key`, сервер хранит
связку «ключ → report_id + тело запроса» в отдельной таблице с ограничением
уникальности на ключ.

- Повтор с тем же ключом и тем же телом → `200` с прежним отчётом и его текущим
  статусом; нового Job нет, даже если прежний уже в `failed`.
- Тот же ключ с другим `organization_id` → `409 idempotency_conflict`: это
  ошибка клиента, молча подменять отчёт нельзя.
- Ключа нет → запрос отклоняется с `invalid_params` (деталь: поле Idempotency-Key).

Повтор после таймаута клиент делает тем же ключом — тогда второй ответ возвращает
уже созданный отчёт, дублей не возникает.

## Рассмотренные альтернативы

- **Ничего не делать, пусть клиенты сами не дублируют.** Переносит проблему
  на самых слабых участников (человек с curl) и противоречит требованию курса
  об идемпотентной операции.
- **Естественный ключ `organization_id`: один отчёт на организацию.** Ломает
  законный сценарий «перезапустить разбор через неделю, накопились новые отзывы».
- **Окно времени на ключ вместо вечного хранения.** Усложняет семантику и тесты;
  объём таблицы для учебного сервиса не проблема.

## Цена решения

Таблица ключей растёт и требует очистки по политике хранения; конфликт тела
нужно явно тестировать (у нас это негативный тест из сценария 2).

## Условия пересмотра

Появится аутентификация клиентов — ключ можно будет привязать к владельцу;
объём таблицы станет проблемой — окно устаревания и фоновая чистка.
